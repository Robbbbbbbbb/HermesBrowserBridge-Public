Hermes Browser Bridge

Connection and privacy settings for this device.

Chrome sometimes loads a page in the background before you navigate to it (Settings → Performance → Preload pages). If another extension — a password manager especially — has injected a frame into that preloaded page, Chrome refuses to let this extension attach to the tab at all, and the failure looks unrelated to preloading. This applies immediately (not on Save, below) and changes a Chrome-wide setting, not just this extension's own preference — every site may load slightly slower as a result. Off by default.

Every origin you've set a mode for in the popup keeps that exact mode — this only decides what a site gets the first time Hermes attaches to it, before you've made a choice for it there. Reported to the gateway (on connect, and immediately whenever you change it here) and stored per device, so it's this extension's own setting, not only something an operator can set in the gateway's config.yaml. Defaults to full: any tab you attach is readable and drivable right away. Set it to request to get an approval prompt the first time instead, or off to refuse an unconfigured site outright.

Attaching a tab (or acting in one) takes a driving lease on it, so two agent sessions can never interleave clicks on the same tab — every act call renews it. With Unlimited, a tab stays with the session that attached it until that session releases it, the user clicks Stop or Release all, or the tab is detached. Other agent sessions are refused that tab meanwhile. Reported to the gateway (on connect, and immediately whenever you change it here) and stored per device, same as Default access above. Defaults to 60 seconds, matching today's behaviour.

A committing action is one that's hard to undo — submitting a form, or clicking something named Finish, Submit, Send, Pay, Purchase, Buy, Place order, Delete, Remove, Confirm, Publish, Transfer, Deploy or Power off. Auto proceed (default) keeps today's behaviour: the action runs immediately and is only labelled in the audit log. Pause for confirmation requires the agent to explicitly confirm the action AND you to approve it in the popup first, whatever that site's own access mode already allows. Reported to the gateway (on connect, and immediately whenever you change it here) and enforced there, same as Default access and Tab lease above.

Before any snapshot, page read or screenshot layout description leaves this machine, the extension scans it for the kinds checked below and replaces each match with a marker like [redacted:card]. The gateway re-checks on arrival as a second, independent pass — but it honours this same policy: a kind you switch off here is off end to end, not just on this side of the wire. It never quietly comes back at the gateway.

These five apply to every site the same way — this is one policy for this device, not a per-site setting. To protect one site more than the rest, set that origin's mode in the popup.

Every change here — on or off, either direction — is written to the gateway's audit log: which device, and the full policy before and after. Turning a protection off is a deliberate, traceable choice, not a silent one. Nothing blocks the change; it is your preference for your own machine.

What the agent is allowed to do, as opposed to Redaction above, which governs what it's allowed to see. Unlike Redaction, every toggle below fails closed: leaving one off — or never touching this page at all — refuses that capability, at the extension, at the gateway, and at the approval prompt. Nothing here is granted by default except the two already-safe ones (dismissing a dialog, reading the origin-scoped downloads list).

Empty means deny every local-path upload, even with Upload a local file switched on above — enabling that checkbox alone grants nothing.

What you see in the browser itself while Hermes is attached to a tab and working in it — separate from the pairing/connection status above. All three default on: the whole point of this extension is that an agent is driving a browser you're sitting in front of, and an agent you can't see moving is the failure mode to design against. See docs/presence.md for exactly what each one looks like and its honest limits.

How long a click/type/key/scroll waits for the pointer to arrive before Hermes acts. Normal and Fast both show the travel; Off skips it and jumps instead, which is the quickest but least visible option. Whichever you pick, Hermes automatically uses Fast instead of Normal whenever the shared tab isn't the active tab of a focused window — nobody is watching it, so there's nothing to gain from the slower glide. Off stays Off either way. This never switches tabs or windows on your behalf.
